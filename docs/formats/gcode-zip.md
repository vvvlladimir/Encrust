# The `.zip` of greyscale PNGs

What a Phrozen Shuffle, a Phrozen Sonic, a Phrozen Transform, a Wanhao CGR, a Wanhao D8 and
a Kelant S400 read: a plain zip holding one gcode program, two previews and one eight-bit
greyscale PNG per layer. Eleven machines in the shipped catalogue carry `output = "zip"`.

Like `.sl1` it is an archive rather than a binary container, and unlike `.sl1` it has no
settings file at all: the program **is** the file, and the board executes it line by line.
Everything a layer does is in that layer's own block, so this is the one container we write
whose per-layer values cost nothing — see ADR 0167.

## Where the knowledge comes from

| Source | What it settles |
|---|---|
| Two independent open-source readers and writers of the archive | The entry names, the header keys and their order, and the shape of a layer block |
| A reference program a machine of this family printed | That the blocks are absolute moves in mm, speeds in mm/min and dwells in milliseconds |

Three things the reference settles:

1. **Layers are numbered from one**, `1.png` upwards, with no padding and no prefix. The
   two previews are safe from that pattern because they are named.
2. **Z is absolute throughout**, after `G90`: a layer lifts to `z + lift` and comes back
   down to its own `z`, which is where it is exposed.
3. **A dwell is milliseconds** — `G4 P30000` is a thirty-second exposure — and a feed rate
   is millimetres a minute, `F60` being one millimetre a second.

## Shape of the archive

```
preview.png            preview, colour, 954x850
preview_cropping.png   preview, colour, 168x150
1.png                  layer 1, eight-bit greyscale
...
N.png                  layer N
run.gcode              the program the board runs
```

We write the entries in that order, so the program trails the stack it describes: its header
states the resin the stack came to, which is only known once the last layer is cut, and a zip
entry cannot be rewritten once it is closed. A reader looks entries up by name, so the order
does not reach it. Entries are stored rather than deflated, because a PNG is already
compressed.

## The header

The first line names what wrote the file, `;Generated by Encrust-<version>`. Then one
`;key:value` a line, in this order:

| Key | What we write |
|---|---|
| `fileName` | empty: nothing in the archive refers to the file's own name |
| `machineType` | `PrinterProfile::machine_name` |
| `estimatedPrintTime` | seconds |
| `volume` | ml |
| `resin` | `MaterialProfile::name` |
| `weight` | grams |
| `price` | the resin's cost of this print, or 0 for a resin with no price |
| `layerHeight` | mm, the thickest layer in the plan |
| `resolutionX`, `resolutionY` | panel, pixels |
| `machineX`, `machineY` | illuminated area, mm; `machineZ` the travel |
| `projectType` | `Normal`, or `LCD_mirror` for a mirrored panel |
| `normalExposureTime` | seconds |
| `bottomLayExposureTime`, `bottomLayerExposureTime` | seconds, the same value in both |
| `normalDropSpeed` | retract speed, mm/min |
| `normalLayerLiftSpeed`, `normalLayerLiftHeight` | mm/min and mm |
| `zSlowUpDistance` | 0 |
| `bottomLayCount`, `bottomLayerCount` | the bottom block, the same value in both |
| `mirror` | 0 or 1 |
| `totalLayer` | the stack's layer count |
| `bottomLayerLiftHeight`, `bottomLayerLiftSpeed` | mm and mm/min |
| `bottomLightOffTime`, `lightOffTime` | seconds |
| `bottomPWMLight`, `PWMLight` | 0 to 255 |
| `antiAliasLevel` | 8 where the masks carry coverage grey, 1 where they are binary |

Two pairs of keys carry one value each — `bottomLay…` and `bottomLayer…`, `bottomLayCount`
and `bottomLayerCount`. Two generations of this header spell them differently and a reader
takes whichever it knows, so both are written.

`mirror` and `projectType` say how the panel is mounted, not what the masks were drawn as,
as in every other container we write (ADR 0134).

## The program

The header is followed by the opening block, one block per layer, and the closing block:

```gcode
;START_GCODE_BEGIN
G21;Set units to be mm
G90;Absolute positioning
M17;Enable motors
M106 S0;Turn LED OFF
;<Slice> Blank
G28 Z0;Home Z
;END_GCODE_BEGIN

;LAYER_START:0
;PositionZ:0.05mm
M6054 "1.png";Show image
G0 Z5.05 F60;Z Lift (1)
G0 Z0.05 F150;Retract (1)
G4 P500;Wait before cure
M106 S255;Turn LED ON
G4 P30000;Cure time/delay
M106 S0;Turn LED OFF
;<Slice> Blank
;LAYER_END

;START_GCODE_END
M106 S0;Turn LED OFF
G0 Z15 F60;Z Lift (1)
G0 Z200 F60;Move Z
M18;Disable motors
;END_GCODE_END
;<Completed>
```

`M6054` names the image to show and `;<Slice> Blank` puts it out again. A dwell is written
only where there is something to wait for: a resin waiting by a light-off delay gets one
`G4` before the light goes on, and one that rests gets its three rests around the peel
instead — before the lift, after the lift and after the retract (`MaterialProfile::waits`).

A retract shorter than the lift is written as two moves, because the plate has to stand at
the layer's own Z before the light goes on. A bottom layer uses the bottom lift distance,
speed and PWM, and comes back down from exactly where it went, as in every other container.

## What the container cannot carry

Nothing of the stack: every number is per layer, so an exposure banded by height and a stack
of mixed thicknesses are both written as they stand.

What it cannot carry is a second lift, a second retract, or an acceleration — the generation
of firmware this archive belongs to has none of them, and our own profiles state none either.

## Two zips, one extension

Both this and the `.sl1` start `PK`, so a file whose name says nothing is told apart by what
is inside it: an archive holding `run.gcode` is this one, and the sniffer falls back to the
`.sl1` reader otherwise (`core-pipeline`'s `read`). A zip of nothing but numbered PNGs — the
same images with the program left out, which a machine of this family also accepts and reads
its own stored profile for — is refused, because none of the numbers a reader shows would be
in the file.

A second family writes a zip under this extension for Klipper-based boards, whose program is
not this one; the catalogue generator makes a source profile naming that firmware class wait
rather than writing it a file this shape (`xtask`'s `containers`).
